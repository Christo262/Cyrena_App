# Cyréna — Coding

This module contains all coding-related extensions for Cyréna.

`coding.slnx` is the solution file used to develop and build everything in this module.

---

## What Lives Here

The coding module is responsible for the parts of Cyréna that interact directly with real codebases — reading project structure, making file edits, running build loops, and persisting structured knowledge back to the project.

This is not a generic code generation layer. It is a constrained engineering agent designed for predictable, reversible behavior inside real projects.

---

## Responsibilities

**Iterative engineering loop** — each action runs through a controlled sequence: read the project plan, search API References, inspect relevant files, make a minimal change, build and validate, repair if needed, summarise, and persist knowledge. Chat memory resets each iteration; structured knowledge survives.

**Architecture enforcement** — the agent cannot invent arbitrary folder layouts or escape the project boundary. Structure rules are domain-specific but consistently enforced.

**API Reference management** — structured technical documents generated by the AI and stored with each project. These describe APIs, architecture rules, contracts, and module behavior. They act as persistent memory that lets the agent reason beyond context window limits.

**Version control and rollback** — a rolling backup of up to 20 versions is maintained across sessions, making it easy to review or roll back to any recent state.

---

## Domain Support

The built-in domain support (.NET, Arduino, PlatformIO, and others) is implemented here as extensions. Each domain has its own structure rules and prompts, but shares the same core agent architecture. New domains are added by building additional extensions — see the [contributing guide](../../contributing.md) for details.

---

## Contributing

If you are adding a new domain, fixing agent behavior, or extending an existing extension:

- Follow the existing extension pattern — built-in domains are the reference implementation
- Keep changes minimal and targeted; the agent is designed around disciplined, reversible edits and contributions to it should reflect the same discipline
- Update or add API Reference documents where relevant
- Test against at least one real project before submitting

See the root [readme](../../readme.md) for the full architecture overview and project philosophy.
